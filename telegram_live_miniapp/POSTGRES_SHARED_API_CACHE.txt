LIVE ZOT — общий PostgreSQL-кэш данных

Что изменено:
- Каждый успешный ответ API-Football сохраняется не только в Redis, но и в PostgreSQL.
- Другой пользователь получает уже сохранённые данные и не создаёт повторный запрос к API-Football.
- Кэш охватывает карточки матчей, статистику, события, составы, команды, клубы, игроков, лиги, таблицы и последние матчи.
- Параметр refresh не создаёт новые записи: обновлённый ответ заменяет одну общую запись.
- Завершённые матчи с полученными данными сохраняются без срока окончания.
- Пустые данные завершённого матча проверяются повторно через 6 часов, чтобы не заморозить поздно опубликованную статистику.
- При временной ошибке API-Football бот показывает последнюю сохранённую версию из PostgreSQL.
- Redis остаётся быстрым первым уровнем кэша, PostgreSQL — постоянным источником сохранённых данных.

Настройки Railway (необязательно):
API_FOOTBALL_POSTGRES_CACHE_ENABLED=1
API_FOOTBALL_POSTGRES_STALE_FALLBACK=1
API_FOOTBALL_FINAL_EMPTY_RECHECK_SECONDS=21600

Проверка после деплоя:
Откройте /health и найдите блок api_football_persistent_cache.
